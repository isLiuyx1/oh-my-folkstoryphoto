# 自审、修订与返修闭环

## 通用规则

- 自审必须基于实际文档或实际图片，不得根据“提示词写得很好”推定通过。
- 每个失败项最多自动修复一次，之后重新检查同一标准。
- 只有实际返回候选图且内容审查失败才计为返修；网络错误、超时和无候选文件不增加 `repair_count`。
- `transport_blocked` 是传输状态，不是内容审查结论；跳过该项继续全部可运行任务，队列结束后统一写入《生成阻塞报告》，最终验收前再解决缺图。
- 二次失败设为 `needs_user`；记录证据、尝试和建议，不得降级为“可接受”。
- `07-制作资料/06-审查报告/01-自审记录.md` 写人类可读结论，`08-系统文件/review-state.json` 写机器可读状态。
- 正式原图生成期间不做技术或内容审查。全部原图齐备并展示编号总览后，由用户选择全审、指定图号审查或跳过；不得立即执行返修。

## 真实性方案自审

创建故事前检查 `00-真实性方案.md`：主采集设备唯一、辅助设备不超过两种；每台设备的年代、持有者、剧情来源、原始比例、横竖拍规则、三种现场状态、原生叠字策略和质感锚点完整。时间码、`PLAY`和电量标识只在设备与年代成立时使用。

通过后进入 `awaiting_realism_approval` 并停止。用户批准时保存哈希并创建故事文件；不得用默认“手机伪纪录”静默替代这一门槛。

## 故事脚本自审

第一次用户确认前只检查 `01-故事脚本.md`：

1. 核心矛盾、主角动机和结局完整。
2. 现实基线、异常入口、升级、撤离、验证和最终证据形成因果链。
3. 第一人称叙述自然，没有提前被分镜数量和视觉细节绑死。
4. 原典、网络解读和虚构边界在故事层面不误导。

故事通过后保存用户当前文件哈希；不得用尚未生成的分镜或提示词作为第一次批准条件。

## 分镜与生产资料自审

第二次用户确认前检查：

1. 标题、故事、分镜、字幕、提示词和发布说明图数一致。
2. 专业分镜严格为五列，能直接看清每张图拍什么、怎么拍和表达什么。
3. 专业分镜与 AI 分镜图号、顺序和核心画面一致。
4. 每图只有一个主要信息点；关键场景原生文字的载体和精确内容已登记，发布字幕与画面原生文字明确分离。
5. 每张具备完整可信拍摄事件和时代设备信息。
6. 人物、服装、道具、地点、天气和时间连续。
7. 普通相册测试通过；前 60% 不像连续摆拍肖像。
8. 创作方案包含完整八段式节拍；每 3–5 图有新证据、因果转折或认知升级，超过五图的段落至少有两个有效节拍。
9. 删图测试通过；同地点、同动作或同异常没有连续重复两张以上，除非后一张新增可验证信息。
10. 调查悬疑题材优先使用至少四类证据载体，每类均可追溯形成者、时间、获取途径和保留原因。
11. 发布字幕非空、不超过48个可见字符，多数约4–28字，不机械复述画面。
12. 通过连续三图测试：相邻2–3张能自然承接，前图代词、短句、停顿和没说完的反应可以保留，但没有空洞悬念占位句。
13. 声音卡与知识边界成立；强调线索已回收，技术词只出自合理的文件或人物。
14. 最后 2–4 图包含结果或余波，最终证据能回扣至少三个前文细节，不以单纯贴脸惊吓结束。
15. 原典、网络解读和虚构边界清楚；视觉参考只转换抽象方法，不复制具体故事元素。
16. schema v5/v6 AI分镜使用批准的采集配置ID，主设备至少覆盖一半，设备可见性物理成立。
17. 普通基线、最差拍摄条件、首次重大异常各且仅标记一张校准图。

发现失败时同步修改所有受影响文件，而不是只改一张分镜。用户修改已批准故事或分镜时先运行 `reopen-gate`，不得继续使用失效哈希。每个失败项修订一次后复查；仍失败则设为 `needs_user`。

## 参考图自审

检查身份锚点、年龄、发型、固定服装、道具结构、地点入口和空间关系、故事年代合理性。参考图用于锁定，不按正式手机抓拍红旗判分。

使用 `record-reference-review` 保存结构化问题。首版失败时从原始参考来源自动重生一版，不把有缺陷的首版作为输入；第二版仍失败时将该参考项设为 `needs_user`。继续审查其他参考任务，但所有必需参考项通过前不进入正式生图。

## 用户选择后的单图自审

schema v6正式原图生成期间不执行本节。全部候选齐备并展示编号总览后，仅对用户选择的图号执行；三张真实性校准和返修图始终执行。

必须同时：

1. 查看原尺寸图片；
2. 验证候选为精确竖版 4:5；竖版 2:3 只能在主体安全区内规范化，横图直接失败；
3. 将该图与字幕、可信拍摄事件和参考图对照；
4. 在联系表中检查全篇风格与连续性；
5. 写入结构化真实性审查JSON，再记录非关键摄影红旗。

若分镜登记了场景原生文字，还必须检查：文字是否位于指定载体、是否逐字正确、语言和年代是否合理、是否确为虚构品牌。没有登记关键文字时允许自然环境文字，但清晰可读的无意义乱码仍失败。发布字幕、说明标题、水印、平台 UI 浮层和假相机 HUD 不得出现在图片中；设备屏幕内部的剧情 UI 不属于浮层。

监控、旧照片、地图或电脑内容若本身为横向，必须检查其是否作为实体载体自然出现在竖版拍摄事件中；直接横图加上下黑边属于内容失败。同一证据来源的设备质感必须连续，后段不得无原因电影化或游戏化。

机位物理、计划外设备、采集配置、非电影化、身份、关键道具、连续性和缺陷因果八项必须逐一检查。不能用“提示词要求了”代替查看实际图片；机位不可能、设备穿帮、电影化、人物错误或关键道具错误中的任一项都是硬失败。

### 返修方式

- **整图重生成**：拍摄者不可能、人物无故看镜头、摆拍、最佳展示角度、电影光线/景深、第一视角穿帮、整体设备年代错误。
- **编辑返修**：身份、地点、机位和整体语言正确，仅有关键文字缺失或错字、清晰乱码、小范围肢体/物体结构或指定异常强度问题。
- **改变机位后重生成**：严重手脚、车辆、船只、多人融合或建筑结构错误。

所有返修重复不变量。原候选和修正版使用版本化文件名。

### 返修门槛

- 通过原图立即登记 `pass`。
- 未通过原图登记问题、建议 `edit`/`regenerate` 和红旗，保持原候选不变。
- 用户选择的图号完成首审后汇总返修报告；报告必须给出图号、问题、建议方式和不变量。
- 未收到用户对全部或指定图号的明确批准前，不调用任何返修生图。

## 最终全篇自审

用户选择跳过时不再逐图检查内容，只验证manifest、编号和交付文件能否生成。局部审查的内容结论只覆盖实际被选图片。

- 普通相册测试通过，至少三种拍摄位置；拍摄来源严格符合批准的主设备加最多两种辅助设备；调查悬疑优先具备至少四类可追溯证据载体。
- 现实/线索/异常/终局比例合理，前段未泄露完整奇观。
- 同一设备的动态范围、白平衡、锐化和夜景能力连续。
- 身份、服装、地点、车辆和关键道具可追踪。
- 每 3–5 图有有效节拍，删图测试通过；最后 2–4 图包含结果或余波并回扣至少三个前文细节。
- 制作期发布 manifest 只引用 `pass` 图片；最终 manifest 必须覆盖全部计划图号。
- 发布字幕、场景原生文字、提示词、最终图片和发布说明编号一致；发布字幕未被叠入图片。
- AI 与虚构声明完整。

全部通过后才进入 `complete`。
