# 验收清单

## 单图硬失败

任一项出现即失败：

- 正式候选不是精确竖版 4:5，或由横图大幅裁切伪装成竖版；
- 横向监控、旧照片、地图或电脑内容被直接加上下黑边放入竖版成片，而不是作为实体载体被拍摄；
- 拍摄者、拍摄位置或第一视角逻辑不可能；
- 当前采集设备作为视角来源却完整出现在画面，且没有登记第二拍摄源；
- 非自拍、合影、定时照中的人物无故直视镜头或停止动作摆拍；
- 画面像宣传照、电影剧照、概念图、游戏截图或专业器材展示；
- 同一证据来源的设备质感无原因变化，或后段突然电影化、游戏化、海报化；
- 设备能力与故事年代不符，或同段落摄影介质无原因变化；
- 主角换脸、年龄明显变化、固定服装或地点结构漂移；
- 多指、断肢、融合人物、重复人物、严重车辆/船只/建筑错误；
- 关键场景原生文字缺失、错字或不在指定载体，或出现清晰可读的无意义乱码；
- 图片内出现后期字幕、说明性标题、水印、平台 UI 浮层或假相机 HUD；
- 出现真实品牌名或 Logo；虚构品牌及场景内设备屏幕 UI 不因此失败；
- 前段提前出现最终奇观；
- 图片无法独立对应字幕或承担多个冲突信息点。

## 七项摄影红旗

逐张计数：

1. 人物居中；
2. 人物直视镜头；
3. 光线均匀且脸部完美补亮；
4. 前景和边缘完全干净；
5. 人物全身、道具和背景都被完整展示；
6. 全画面商业级锐利；
7. 构图像肖像、剧照、宣传照或器材展示。

同一张达到三项即失败。返修优先改变拍摄行为、机位和人物视线，不得只加噪点。硬失败不参与计数：机位不可能、设备穿帮、电影化、人物错误或关键道具错误只出现一项也必须失败。

## schema v5结构化审查

`mark-pass --review-file` 的JSON必须逐项填写：

- `viewpoint_physics`
- `unplanned_recorder_absent`
- `capture_profile_match`
- `not_cinematic`
- `identity_match`
- `key_prop_match`
- `continuity_match`
- `defects_are_causal`

值只能为 `pass`、`fail`、`na`。前四项不得为 `na`；人物或关键道具确实不在本镜时，对应项才可为 `na`。任一 `fail` 阻止通过。候选版本和审查文件哈希必须保留，`mark-pass` 不得清空历史失败。

## 单图通过条件

- 无硬失败；
- 摄影红旗少于三项；
- 拍摄者、原因、站位、人物意识、保留理由和设备结果均可解释；
- 构图/成像不完美由场景导致，不是统一滤镜；
- 身份、空间、时代和字幕对应正确。
- 关键场景原生文字逐字正确；发布字幕没有叠入图片。

## 整篇

- 图数、分镜、发布字幕、场景原生文字、提示词和发布说明一致；
- 专业分镜严格为“图号、画面拍什么、镜头怎么拍、人物在做什么、这张图要表达什么”五列，不混入设备、哈希、风险或传输字段；
- 专业分镜与 AI 生成分镜图号、顺序和核心画面一致；
- 默认图数为 30–39；用户指定其他图数时，创作方案已记录覆盖原因；
- 八段式节拍完整，每 3–5 图有新证据、因果转折或认知升级，超过五图的段落至少包含两个有效节拍；
- 删图测试通过；同一地点、动作或异常不连续重复两张以上，除非后一张新增可验证信息；
- 调查悬疑优先使用至少四类证据载体，形成者、时间、获取途径和保留原因均可追溯；
- 发布字幕一图一句、一句一推进，建议 12–36 个汉字、硬范围 8–48 个可见字符，不机械复述画面；
- 每句发布字幕都有明确主语或对象和具体事件，单独配合当前图片即可理解；代词有指向，不使用空洞悬念占位句；
- 现实生活约占 60%，异常逐步增加；
- 至少三种拍摄位置；拍摄来源按已批准真实性方案执行，不再强制为了变化而使用两种设备；
- 主采集设备承担至少一半正式图，辅助设备不超过两种且首次出现前已有剧情伏笔；
- 普通基线、最差拍摄条件、首次重大异常三张校准图均通过并保存用户批准哈希；
- 同一角色、地点、设备、车辆和道具连续；
- 最终证据重新解释至少三个前文细节；
- 最后 2–4 图包含结果或余波，不只用贴脸怪物或突发惊吓收尾；
- 恐怖不靠连续鬼脸，庄严题材不被无故恐怖化；
- 来源、推测与虚构边界清楚；
- 最终成片全部为 1080×1350 PNG。

## 停止门槛与非阻断异常

- 新项目必须先展示 `00-真实性方案.md` 并等待确认；批准前不得创建故事文件；
- 故事脚本自审后必须停止等待第一次确认；批准前不得生成分镜和生产资料；
- 专业分镜及生产资料自审后必须停止等待第二次确认；批准前不得生成参考图；
- 参考图自审后必须停止等待第三次确认；批准前不得生成正式图片；
- 参考图批准后只生成三张校准图；校准联系表获用户批准前不得生成其他正式图片；
- 批准后的故事、专业分镜、AI 分镜或参考图哈希变化时必须回退相应门槛；
- 全部原图首审结束并生成返修报告后，必须停止等待用户批准全部或指定返修图号；
- 自动修复一次后仍存在任何硬失败时，只把该内容项设为 `needs_user`；先继续其他独立可运行项；
- 身份或关键地点母版第二版仍无法稳定时，阻止参考图批准，但继续其他参考任务；
- 合格图片数不足且继续生成将超过返修上限时，记录缺项并继续不受影响的任务；
- 两个不同任务出现相同后端传输错误时记录后端健康告警，但继续逐项尝试，不触发阻断性后端熔断；
- 单项耗尽三档参考恢复后标为 `transport_blocked`；不得停止整个项目，继续其他参考图、分镜、返修和批次，全部可运行项结束后统一生成《生成阻塞报告》；
- 用户未明确授权时不得切换 CLI、API 或其他模型；
- 文化、宗教、现实地点或真实事件的改编边界无法安全确定。
