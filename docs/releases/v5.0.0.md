# oh-my-FolkStoryPhoto v5.0.0

v5 把“像真实私人照片”从提示词偏好升级为一套可批准、可校准、可审计的生产流程。现在技能会先确定谁在拍、用什么设备、为什么拍以及设备在不同现场条件下会怎样失真，再进入故事和分镜。

## 主要更新

- 新增真实性方向确认：项目从 `00-真实性方案.md` 开始，明确主设备、最多两种辅助设备、拍摄者、年代、画幅、携带原因和三种现场状态；批准前不创建故事。
- 新增八类设备档案与六张匿名采集质感锚点。锚点只用于学习动态范围、曝光、锐度、色度和业余机位，不复制人物、地点、动作、文字或构图。
- 新增三张真实性校准：普通基线、最差拍摄条件、首次重大异常。三张均使用正式请求、正式参考和正式输出路径，批准后直接作为最终通过图。
- 新增第一视角物理校验：当前采集设备不能无故完整入镜；拍摄者或设备入镜时必须登记镜面、固定机位、接拍或第二采集源等成立原因。
- AI 生产分镜升级至 schema v5，新增采集配置 ID、拍摄者入镜范围、设备可见性和校准角色；主设备至少承担一半正式图。
- 正式提示词增加 260 字符/900 字节硬预算，并拒绝电影感、史诗、英雄机位、HDR、商业摄影和概念图等诱导词。
- 新增逐图结构化真实性审查 JSON。机位物理、计划外设备、采集配置、非电影化、身份和关键道具任一硬项失败，都不能标记通过。
- 真实性返修仍遵循每图最多一次内容返修；返修后硬失败进入 `needs_user`，并保留全部候选和审查历史。

## 同批纳入的 v4.1–v4.4 改进

- 连续编号的工作区与项目目录，用户文档、生产资料、生成过程和系统文件分层保存。
- 故事优先、五列专业分镜、清晰第一人称发布字幕，以及发布字幕与场景原生文字分离。
- 30–39 图八段式长篇证据链、每 3–5 图一次推进、证据来源说明、删图测试和余波结尾。
- 允许招牌、屏幕、文件、标签、设备读数和虚构品牌等场景原生文字；继续禁止后期字幕、水印、平台浮层和假相机界面。
- timeout/no-candidate 自动压缩或拼合参考输入，network error 保持原请求；单图耗尽恢复阶梯后记录跳过，继续下一项和下一批。
- 批次每成功三张或运行十五分钟自动滚动，不增加用户确认。

## 兼容性

- 新项目使用 schema v5。
- schema v1–v4 项目继续按原结构读取和执行，不自动移动、迁移或重写。
- 正式图片仍要求精确竖版 4:5；发布字幕不叠入图片；正式内容返修仍最多一次。

- Python 编译、JSON 解析、技能结构校验和安装预演通过。
